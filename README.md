# dota2-coach

Локальный инструмент: берёт `match_id`, тянет детальные данные матча из OpenDota,
отбирает из них значимое и собирает текстовый промпт. Промпт вставляешь в
ChatGPT/Claude и получаешь разбор игры как от тренера.

Два режима разбора:

* **Один матч** — одна игра подробно, вплоть до конкретного промежутка под лупой;
* **Профиль** — последние N матчей игрока сводятся в кросс-матчевую выжимку и
  разбираются на предмет того, что **повторяется**.

Вывод инструмента — это начало разговора, а не финальный вердикт: модель обязана
предложить конкурирующие гипотезы и задать вопросы, на которые данных нет.

Работает двумя способами — из терминала и через локальную страницу в браузере.
Ни базы, ни истории, ни авторизации: всё живёт на твоей машине.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

Ключ OpenDota не обязателен — API работает и без него, просто с меньшими лимитами.
Если он есть:

```bash
export OPENDOTA_API_KEY=твой_ключ
```

## Запуск: веб-интерфейс

```bash
python -m dota2coach serve
```

Открыть <http://127.0.0.1:8000>. Эквивалент напрямую через uvicorn:

```bash
uvicorn dota2coach.web.app:app --port 8000
```

Базовый вид страницы минимальный — ровно то, без чего нельзя: **ID матча, ID
игрока, кнопка**. Всё остальное лежит под свёрнутым блоком «Расширенные
настройки»: роль, фокус, глубина, модель, промежуток игры, вопрос и уровень.
Casual видит простую форму, power-user разворачивает. Кнопка «Разобрать» →
готовый промпт с кнопками «Копировать» и «Скачать .txt». Веб ничего не пишет в
`output/` — файл отдаёт браузер.

Что есть на странице:

* **Переключатель режимов** сверху — «Один матч» и «Профиль». В режиме профиля
  базовые поля становятся `account_id` + число матчей, а фильтры по герою и
  позиции уезжают в расширенные настройки.
* **Ползунок промежутка** — выбор игрового окна (например 30–40 мин) с
  подсказкой: выбери промежуток, если хочешь максимально детально рассмотреть
  конкретный тайминг игры — действия всех героев в этом окне. По умолчанию
  выключен (значение «весь матч»).
* **Radiant/Dire** как смысловая метка: результат окрашивается в цвета твоей
  стороны, с бейджем вида «Dire · победа». Акцент интерфейса при этом остаётся
  нейтральным — фракции не раскрашивают всё подряд.
* **Подсказки «?»** у каждого поля — что оно делает и как этим пользоваться.
  Открываются по клику (не по ховеру: ховер недоступен с клавиатуры), закрываются
  по Esc или клику вне.
* **Язык** — русский, английский, украинский. Один селектор переключает и подписи
  интерфейса, и язык генерируемого промпта.
* **Тема** — тёмная по умолчанию, светлая по кнопке. Стеклянная эстетика в обеих.
* **Роль** — Auto использует эвристику линии/нетворта; явный выбор позиции 1–5
  переопределяет её только для ★ и меняет критерии оценки и приоритет фактов.
* **Role-aware focus** — для саппортов UI не предлагает `farm` как основной
  фокус, а поднимает `vision` и `enable`.
* **Ссылка вместо ID** — в поле матча можно вставить ссылку с Dotabuff, OpenDota
  или STRATZ, номер извлечётся сам.
* **Оценка токенов** рядом с размером — видно, влезет ли промпт в бесплатный чат.
* **Дисклеймер** под результатом: инструмент даёт данные и промпт, качество
  разбора зависит от модели, в которую его вставят.
* **Плейсхолдеры-примеры** в полях: у вопроса к разбору три примера чередуются
  (пока в поле не начали писать), у поля MMR — без лишней серьёзности.

Флаги: `--port 8080`, `--host 0.0.0.0`, `--reload` (автоперезапуск при правках).
По умолчанию сервер слушает только `127.0.0.1` — наружу не торчит.

Форма запоминает язык, тему, режим, состояние «Расширенных настроек»,
account_id, уровень и опции в localStorage, так что при следующем матче меняется
только ID. `Cmd`/`Ctrl`+`Enter` отправляет форму.

## Запуск: CLI

```bash
python -m dota2coach analyze 8931432366 --me 123456789
```

Не знаешь свой `account_id` — укажи героя, которым играл:

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer"
```

Результат: `output/<match_id>.txt`. Скопируй файл целиком и вставь в чат с LLM.

Если матч ещё не распарсен OpenDota, инструмент сам закажет парсинг и подождёт
(до 3 минут), а потом перезаберёт данные.

## Роль: `--role`

`--role 1|2|3|4|5` задаёт обязанности именно твоего игрока. Без флага всё
работает как раньше: позиция определяется по линии и нетворту.

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer" --role 1
```

| Значение | Роль | Главные критерии |
|---|---|---|
| `1` | Carry | CS@10, GPM, нетворт, предметы, урон, поздние смерти |
| `2` | Mid | темп, руны, XPM, ранний импакт, участие |
| `3` | Offlane | инициация, фронтлайн, пространство, полученный урон |
| `4` | Soft Support | роуминг, стаки, вижн, контроль, ассисты, utility |
| `5` | Hard Support | вижн/детект, стаки, лечение, ассисты, командные предметы |

Для позиций 3–5 смерть не считается ошибкой автоматически: scaffold требует
проверить, дала ли она инициацию, выгодный размен или спасение кора. Для
саппортов CS/GPM не используются как критерии успеха. OpenDota не даёт надёжного
счётчика save events, поэтому prompt использует лечение, участие в боях и
защитные предметы как свидетельства и запрещает выдумывать число сейвов.

## Режимы

Три параметра — роль, глубина и фокус — решают, как оценивать игрока и какие
факты поднять в промпте.

**`--depth quick|deep`** — сколько подробностей. `quick` (по умолчанию) даёт
скелет матча: драфт, скорборд, бенчмарки, перевес команд, мои предметы и раскачку,
лайнинг, сводку боёв. `deep` разворачивает это на все десять игроков.

**`--focus full|laning|fights|farm|draft|vision|tempo|initiation|enable`** —
под какой вопрос затачивается разбор.
Фокус не только раскрывает профильную секцию, но и приглушает остальные, а заодно
задаёт модели акцент внутри разбора по стадиям.

Новые role-aware фокусы:

* `vision` — obs/sen, деварды, детект и информация вокруг объективов;
* `tempo` — руны, ранние киллы/участие, выход с линии, первые тайминги;
* `initiation` — входы в бой, контроль, поглощённый урон и пространство;
* `enable` — стаки, вижн, лечение, участие и командные/защитные предметы.

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer" --depth quick --focus laning
```

Порядок величин на 54-минутном матче:

| | full | laning | fights | farm | draft |
|---|---|---|---|---|---|
| **quick** | 15 КБ | 11 КБ | 29 КБ | 18 КБ | 13 КБ |
| **deep** | 38 КБ | 14 КБ | 36 КБ | 24 КБ | 16 КБ |

`--focus fights` тяжелее остальных намеренно: это поимённая раскладка каждого боя,
ради которой флаг и существует.

## Промежуток под лупой: `--window`

«Разбери мне 30–40» — отдельный запрос, для которого поднимать глубину целиком
было бы расточительством.

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --window 39-44
```

Окно — не секция поверх остального, а **перераспределение внимания**: выбранный
промежуток печатается с максимальной детализацией, а весь остальной матч
ужимается до сводки. Иначе детализация окна утонула бы в общем объёме.

Внутри окна экономии нет сознательно:

* все десять героев поминутно, без прореживания — нетворт, опыт, добивания/денаи;
* убийства с таймингами;
* покупки **включая расходники** — по ним видно, кто готовился к бою, а кто фармил;
* задевшие окно бои поимённо;
* объективы.

Пустое окно печатается как факт («отрезок был пустым»), а не пустой секцией:
иначе модель начнёт достраивать события. В `ОГРАНИЧЕНИЯХ ДАННЫХ` появляется
оговорка, что остальные секции сжаты, — чтобы модель не выдавала за факт то, чего
в промпте нет.

Единственное исключение из сжатия — блок отклонений: из него строятся гипотезы, и
он нужен целиком независимо от разбираемого отрезка.

## Режим «Профиль»: кросс-матчевый разбор

Один матч отвечает на вопрос «что случилось». Десяток матчей отвечает на более
полезный: «что у меня повторяется».

```bash
python -m dota2coach profile 123456789 -n 10
python -m dota2coach profile 123456789 -n 10 --hero "Phantom Lancer"
python -m dota2coach profile 123456789 -n 10 --role 5
```

Результат: `output/profile_<account_id>_<N>.txt`. Базы данных нет — агрегация
живёт в памяти на время запроса.

**Полных данных матчей в промпте нет намеренно.** Десять распарсенных матчей — это
сотни килобайт, в которых утонет любая модель. Наружу уходит только выжимка:

| Секция | Что в ней |
|---|---|
| `ВЫБОРКА` | сколько матчей вошло из запрошенных, какие фильтры |
| `СРЕДНИЕ ПО ВЫБОРКЕ` | винрейт, GPM/XPM/CS@10/нетворт, KDA, участие, лайн-эффективность, худший матч по смертям как контекст к среднему |
| `ТРЕНДЫ ПЕРЦЕНТИЛЕЙ` | средний перцентиль, разброс и направление (свежие матчи против старых), а не перцентиль каждого матча |
| `ПОВТОРЯЮЩИЕСЯ ОТКЛОНЕНИЯ` | главный материал разбора, см. ниже |
| `ПРОФИЛЬ ПО СТАДИЯМ ИГРЫ` | на каких пятиминутках перевес уходит систематически |
| `СОСТАВ ВЫБОРКИ ПО ГЕРОЯМ` | без него средние читать нельзя |
| `МАТЧИ ВЫБОРКИ` | по ОДНОЙ строке на матч — достаточно, чтобы сослаться на конкретную игру |

**Повторяющиеся отклонения.** Паттерн — это отклонение, случившееся не однажды
(порог: 40% выборки и минимум дважды). Считается по тому же детектору, что и в
одиночном разборе, поэтому отдельного списка «типичных ошибок» здесь нет и не
будет — он устарел бы так же, как список важных предметов.

**Профиль по стадиям** отвечает на «стабильно проседаю на 25–35 мин»: для каждой
пятиминутки берётся *изменение* перевеса по золоту и усредняется по выборке.
Уровень перевеса для этого не годится — он тянется из предыдущих стадий, и провал
в мид-гейме выглядел бы как провал во всём лейте.

Отдельно защита от вымысла: поминутные ряды есть только у распарсенных матчей,
поэтому стадии часто опираются на меньшую выборку, чем профиль. Если таких матчей
меньше двух, слово «систематически» не употребляется вовсе — печатается таблица и
честная оговорка. Иначе промпт предлагал бы модели вывести закономерность из
одного наблюдения.

**Вежливость к OpenDota.** Матчи тянутся по одному через общий rate-limiter
(~1 запрос/сек), так что 10 матчей — это порядка 15 секунд. Парсинг
нераспарсенных матчей **не заказывается**: десять ожиданий по три минуты
превратили бы запрос в получасовой. Недоступный матч пропускается, а не рушит
профиль; сколько матчей реально вошло, видно и в промпте, и в ответе API.

Фильтр по позиции работает с оговоркой: серверный фильтр OpenDota знает только
линию, а позиция — наша эвристика, поэтому часть скачанных матчей отбрасывается.
Фильтр по герою терпим к вводу (`pl`, `phantom lancer`), но неоднозначное имя
отвергает с просьбой уточнить, а не берёт молча первого подходящего.

Работают `--model`, `--lang`, `--mmr`, `--note` — так же, как в одиночном разборе.

## Что промпт заставляет модель делать

Промпт — это не «вот данные, разбери». В него вшита методика: правила, которые
модель обязана соблюдать, и жёсткая структура ответа. Обычный игрок получает
разбор уровня power-user, ничего не зная о промптинге.

**Правила**: каждое утверждение — с числом или таймингом из данных; общие советы
(«вардить больше», «фармить лучше») запрещены; сортировка по цене ошибки, а не по
времени; объяснять механизм, а не выдавать правило; не хватает данных — сказать
прямо; сильные стороны называть так же конкретно, как ошибки; разобрать каждое
найденное отклонение — либо объяснить, либо честно отвергнуть; **не подавать
выводы как окончательные**.

**Структура ответа**: Вердикт → Что получилось хорошо → Главный leak с
доказательствами → Разбор по стадиям в порядке важности → 2–4 измеримых действия
(«CS@10 ≥ 55 за счёт…», а не «фарми лучше») → **Гипотезы** → **Вопросы ко мне**.

С `--note` перед вердиктом добавляется раздел 0 — ответ на вопрос игрока.

### Разбор как начало диалога

Последние два раздела и делают вывод началом разговора:

* **Гипотезы** — 2–3 *конкурирующие* версии причины исхода из разных областей
  (драфт, билд и тайминги, ключевые файты, фарм, позиционирование). Для каждой
  требуется доказательство из данных, способ подтвердить или опровергнуть и
  степень уверенности. Версии должны различаться по сути, а не пересказывать одну.
* **Вопросы ко мне** — 2–3 диагностических вопроса про то, чего **нет** в данных:
  намерения, план на игру, коммуникация, что было видно на экране. Например: «игра
  поехала в файте или ещё в драфте?», «есть момент, в котором ты сам не уверен?».

### Статистически необычное в данных

Чтобы гипотезы не выродились в общие места, промпт содержит секцию
`СТАТИСТИЧЕСКИ НЕОБЫЧНОЕ В ДАННЫХ` — отклонения, найденные автоматически. Она
видна при любом фокусе и не приглушается никогда.

Ключевое решение: **никакого списка «важных предметов» или «типичных ошибок»**.
Такой список пришлось бы вести руками, и он всё равно отставал бы от патча и
матчапа. Вместо этого ищутся отклонения в самих данных:

| Что ищем | Как |
|---|---|
| Предмет отстаёт от темпа сборки | ожидаемая минута выводится из накопленной стоимости и GPM, но значимо только превышение над **медианой** отставания по всей сборке |
| Перцентили у краёв | ≤20 или ≥80 для этого героя; низких показываем до трёх, высоких — один |
| Разрыв между метриками | «одно вытянуто, другого нет» |
| Провал в доходе | участок, где GPM просел против личного среднего |
| Кластер смертей | несколько смертей в узком окне — это один эпизод, а не разрозненные ошибки |
| Доля времени мёртвым | против медианы остальных игроков матча |
| Разрыв лайн-эффективности | против соперников по линии |
| Участие в убийствах | на краях распределения |
| Быстрый разворот перевеса | окно, где команда потеряла больше всего относительного золота |

Медиана в первом пункте — важная деталь: без неё у саппорта с вардами и выкупами
флагом помечался бы каждый предмет подряд. Сравнение идёт **с собственной**
сборкой, поэтому «поздний BKB» всплывает сам, как следствие, а не как отдельное
захардкоженное правило.

Каждое отклонение помечено осью (`билд`, `фарм`, `файты`, `линия`,
`позиционирование`) — подсказка, к какой гипотезе его цеплять. Оценок нет: наружу
идёт факт и его контекст. Если отклонений не нашлось, это печатается явно — иначе
модель начнёт додумывать аномалии, которых в данных нет.

## Свой вопрос к разбору: `--note`

Если хочешь разобраться в чём-то конкретном, а не получить обзор «по всем фронтам»,
передай вопрос текстом (у флага есть псевдоним `--ask`):

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --note "почему я так поздно собрал Manta и стоило ли идти в Diffusal?"
```

Что меняется в промпте:

* появляется отдельная секция `## ГЛАВНЫЙ ЗАПРОС ИГРОКА` с твоим текстом;
* первым правилом методики становится «вопрос игрока — главный приоритет»;
* в структуре ответа перед вердиктом добавляется раздел 0 — ответ на твой вопрос;
* в шапку добавляется указатель на этот блок.

Заметка **не меняет объём промпта** — только приоритет разбора. Отбор фактов
по-прежнему задаётся `--depth` и `--focus`, поэтому вопрос про лайн логично
сочетать с `--focus laning`:

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --focus laning --note "почему я слил лайн против Pudge + Hoodwink?"
```

Без флага структура ответа остаётся из семи разделов, без нулевого. Пустая строка
(`--note ""`) считается отсутствием заметки. В режиме профиля заметка работает
точно так же.

## Уровень игрока: `--mmr`

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --mmr "Legend 3500"
```

Принимается и число, и название бракета. Если указан, модель получает прямое
указание калибровать советы под этот уровень: предлагать то, что на нём реально
исполняется, а рекомендуя приём выше уровнем — объяснять, зачем он.

## Под какую модель: `--model`

Данные и методика одинаковы для всех, отличается только упаковка.

| `--model` | Обёртка | Глубина по умолчанию |
|---|---|---|
| `chatgpt` (по умолчанию) | markdown | `quick` |
| `claude` | XML-теги `<role>`, `<match_data>`, `<player_question>`, `<method>`, `<output_format>` | `deep` |
| `gemini` | markdown | `deep` |

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --model claude
```

Claude заметно надёжнее держит границы «данные / вопрос / инструкция», когда они
размечены тегами. Дефолтная глубина — подсказка, а не правило: явный `--depth`
всегда важнее.

## Язык промпта: `--lang`

`ru` (по умолчанию), `en`, `uk`. Переключает **весь** промпт — заголовки, подписи
внутри строк, ограничения и методику, — включая указание модели отвечать на этом
языке. В вебе язык интерфейса и язык промпта переключаются одним селектором.

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --lang en
```

Новый язык добавляется одним файлом в [dota2coach/i18n/](dota2coach/i18n/) —
скопировать `ru.py`, перевести значения, добавить код в `_MODULES`. Офлайн-тест
проверит, что ни один ключ не забыт.

## Прочие флаги

`--no-cache` — не брать матч из локального кэша, сходить в API заново. Сыгранный
матч не меняется, поэтому распарсенный ответ кэшируется в `.cache/` навсегда: это
экономит запросы, когда гоняешь один матч в разных режимах.

## Как это устроено

```
            CLI            веб-страница
             │                   │
             └──────► core ◄─────┘
                       │
DataSource ──► Normalizer ──► FeatureExtractor ──► BundleBuilder ──► текст
(OpenDota)     (Match)        (Features)           (промпт)
                  │                 ▲                   ▲
                  │                 └─── Policy ────────┘
                  │      (--role / --depth / --focus / --note / --window)
                  │
                  └──► ProfileAggregator ──► ProfileBundleBuilder ──► текст
                       (ProfileFeatures)      (мульти-матч промпт)
```

CLI и веб — две тонкие обёртки над `core.generate_prompt()` и
`core.generate_profile_prompt()`. Генерация живёт в одном месте, поэтому обёртки
не могут разъехаться. Оба режима переиспользуют один детектор отклонений: в
профиле «паттерн» — это просто отклонение, встретившееся не однажды.

| Модуль | Ответственность |
|---|---|
| [`core.py`](dota2coach/core.py) | сборка конвейера, `generate_prompt()` и `generate_profile_prompt()` — точки входа для обеих обёрток |
| [`anomalies.py`](dota2coach/anomalies.py) | поиск статистических отклонений — сырьё для гипотез модели |
| [`profile.py`](dota2coach/profile.py) | кросс-матчевая агрегация: средние, тренды, повторяющиеся паттерны, стадии |
| [`scaffold.py`](dota2coach/scaffold.py) | методика разбора: правила для модели и структура ответа |
| [`render.py`](dota2coach/render.py) | упаковка под модель (markdown / XML) и дефолтная глубина |
| [`i18n/`](dota2coach/i18n/) | все тексты проекта — и промпта, и интерфейса |
| [`sources/base.py`](dota2coach/sources/base.py) | контракт источника: «дай `match_id` — получи `Match`» |
| [`sources/opendota.py`](dota2coach/sources/opendota.py) | HTTP к OpenDota, заказ парсинга, кэш сырого ответа |
| [`normalize.py`](dota2coach/normalize.py) | единственное место, знающее формат OpenDota |
| [`model.py`](dota2coach/model.py) | внутренняя модель матча — общий язык приложения |
| [`constants.py`](dota2coach/constants.py) | справочники: герои, предметы, способности, баффы |
| [`policy.py`](dota2coach/policy.py) | что показывать: роль, тиры, глубина, focus, окно и заметка |
| [`features.py`](dota2coach/features.py) | отбор фактов и производные (переломы, сборки, исходы боёв) |
| [`bundle.py`](dota2coach/bundle.py) | форматирование промпта |
| [`web/app.py`](dota2coach/web/app.py) | FastAPI: страница, `POST /api/analyze` и `POST /api/profile` |
| [`web/static/index.html`](dota2coach/web/static/index.html) | вся страница: вёрстка, стили и скрипт в одном файле |

### API

`POST /api/analyze` принимает `{match_id, account_id, hero, role, depth, focus,
model, lang, note, mmr, window_start, window_end}` и возвращает
`{prompt, filename, size_bytes, role, parsed, side, win, window, warning, …}`.
`role: null` означает автоэвристику, `role: "1"…"5"` — явное переопределение
позиции своего игрока. `depth: null` означает «взять дефолт модели». Окно
передаётся двумя числами, а не строкой «30-40», чтобы его валидировал pydantic, а
не разбор текста; `side` и `win` нужны интерфейсу для фракционной окраски
результата.

`POST /api/profile` принимает `{account_id, matches, hero, role, model, lang,
note, mmr}` и возвращает `{prompt, filename, size_bytes, analyzed, requested,
unparsed, winrate, warning, …}`. У него своё окно таймаута: выборка тянется
дольше одиночного разбора.

Схема — на <http://127.0.0.1:8000/api/docs>.

Блокирующие запросы к OpenDota уходят в пул потоков, поэтому сервер не залипает
на время парсинга. Коды ошибок: 404 — матча нет, 400 — не опознан игрок (в ответ
приходит список героев матча с их account_id), 429 — лимит OpenDota, 502 — сеть,
504 — матч всё ещё парсится. Для профиля добавляются 404 «нет матчей под фильтры»
и 400 «имя героя неоднозначно». Если матч распарсен не полностью, промпт всё равно
возвращается, но с предупреждением в поле `warning`; в профиле `warning` сообщает
о неполных данных или о недоборе выборки.

Смысл разделения — в `DataSource`. Когда появится собственный парсер реплеев
(Тир 3), он станет ещё одной реализацией этого интерфейса и вернёт тот же
`Match`; `FeatureExtractor`, `BundleBuilder` и CLI менять не придётся.

Что именно попадает в промпт, из какого поля OpenDota и в каком режиме — в
[docs/FEATURE_SPEC.md](docs/FEATURE_SPEC.md).

## Проверка без сети

```bash
python tests/selftest_offline.py
```

Гоняет синтетический матч через весь конвейер и проверяет узкие места: срезание
шаблонов талантов, поглощение компонентов предметов, фильтр нулевых баффов,
определение сгруппированного драфта, компактность `quick` относительно `deep`,
наличие guardrails и разделов ответа, приоритет заметки, совпадение данных между
markdown- и XML-упаковкой, полноту всех трёх словарей и отсутствие русских строк
в английском промпте. Дополнительно сравнивает carry и hard support на одном
матче: role override, набор метрик, правила смертей, role-aware бенчмарки и новые
`vision/tempo/initiation/enable` focus.

Проверяются и новые механики:

* **детектор темпа сборки** — что предмет ловится по отставанию от *собственного*
  темпа, а сборка, целиком сдвинутая на 10 минут (типичный саппорт с вардами), не
  порождает ни одной аномалии;
* **окно** — разбор `--window`, отказ от некорректных границ, максимум внутри окна
  и сжатие всего остального до сводки;
* **профиль** — что единичное отклонение не становится паттерном, что тренд не
  объявляется на трёх матчах, что стадии видят провал после 25-й минуты, и что в
  мульти-матч промпт **не утекли** полные данные матчей;
* **защита от вымысла** — если поминутные ряды есть у одного матча, слово
  «систематически» в промпте не появляется.
