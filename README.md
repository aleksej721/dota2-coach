# dota2-coach

Локальный инструмент: берёт `match_id`, тянет детальные данные матча из OpenDota,
отбирает из них значимое и собирает текстовый промпт. Промпт вставляешь в
ChatGPT/Claude и получаешь разбор игры как от тренера.

Работает двумя способами — из терминала и через локальную страницу в браузере.
Ни базы, ни истории, ни авторизации: всё живёт на твоей машине.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

Ключ OpenDota не обязателен — API работает и без него, просто с меньшими лимитами.
Если он есть:

```bash
export OPENDOTA_API_KEY=твой_ключ
```

## Запуск: веб-интерфейс

```bash
python -m dota2coach serve
```

Открыть <http://127.0.0.1:8000>. Эквивалент напрямую через uvicorn:

```bash
uvicorn dota2coach.web.app:app --port 8000
```

Одна страница со всеми опциями: ID матча, account_id, роль (Auto или позиции 1–5),
тумблер `quick`/`deep`, role-aware фокус, модель, вопрос и уровень. Кнопка
«Разобрать» → готовый
промпт с кнопками «Копировать» и «Скачать .txt». Веб ничего не пишет в `output/` —
файл отдаёт браузер.

Что есть на странице:

* **Подсказки «?»** у каждого поля — что оно делает и как этим пользоваться.
  Открываются по клику (не по ховеру: ховер недоступен с клавиатуры), закрываются
  по Esc или клику вне.
* **Язык** — русский, английский, украинский. Один селектор переключает и подписи
  интерфейса, и язык генерируемого промпта.
* **Тема** — тёмная по умолчанию, светлая по кнопке. Стеклянная эстетика в обеих.
* **Роль** — Auto использует эвристику линии/нетворта; явный выбор позиции 1–5
  переопределяет её только для ★ и меняет критерии оценки и приоритет фактов.
* **Role-aware focus** — для саппортов UI не предлагает `farm` как основной
  фокус, а поднимает `vision` и `enable`.
* **Ссылка вместо ID** — в поле матча можно вставить ссылку с Dotabuff, OpenDota
  или STRATZ, номер извлечётся сам.
* **Оценка токенов** рядом с размером — видно, влезет ли промпт в бесплатный чат.
* **Дисклеймер** под результатом: инструмент даёт данные и промпт, качество
  разбора зависит от модели, в которую его вставят.

Флаги: `--port 8080`, `--host 0.0.0.0`, `--reload` (автоперезапуск при правках).
По умолчанию сервер слушает только `127.0.0.1` — наружу не торчит.

Форма запоминает язык, тему, account_id, уровень и режимы в localStorage, так что
при следующем матче меняется только ID. `Cmd`/`Ctrl`+`Enter` отправляет форму.

## Запуск: CLI

```bash
python -m dota2coach analyze 8931432366 --me 123456789
```

Не знаешь свой `account_id` — укажи героя, которым играл:

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer"
```

Результат: `output/<match_id>.txt`. Скопируй файл целиком и вставь в чат с LLM.

Если матч ещё не распарсен OpenDota, инструмент сам закажет парсинг и подождёт
(до 3 минут), а потом перезаберёт данные.

## Роль: `--role`

`--role 1|2|3|4|5` задаёт обязанности именно твоего игрока. Без флага всё
работает как раньше: позиция определяется по линии и нетворту.

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer" --role 1
```

| Значение | Роль | Главные критерии |
|---|---|---|
| `1` | Carry | CS@10, GPM, нетворт, предметы, урон, поздние смерти |
| `2` | Mid | темп, руны, XPM, ранний импакт, участие |
| `3` | Offlane | инициация, фронтлайн, пространство, полученный урон |
| `4` | Soft Support | роуминг, стаки, вижн, контроль, ассисты, utility |
| `5` | Hard Support | вижн/детект, стаки, лечение, ассисты, командные предметы |

Для позиций 3–5 смерть не считается ошибкой автоматически: scaffold требует
проверить, дала ли она инициацию, выгодный размен или спасение кора. Для
саппортов CS/GPM не используются как критерии успеха. OpenDota не даёт надёжного
счётчика save events, поэтому prompt использует лечение, участие в боях и
защитные предметы как свидетельства и запрещает выдумывать число сейвов.

## Режимы

Три параметра — роль, глубина и фокус — решают, как оценивать игрока и какие
факты поднять в промпте.

**`--depth quick|deep`** — сколько подробностей. `quick` (по умолчанию) даёт
скелет матча: драфт, скорборд, бенчмарки, перевес команд, мои предметы и раскачку,
лайнинг, сводку боёв. `deep` разворачивает это на все десять игроков.

**`--focus full|laning|fights|farm|draft|vision|tempo|initiation|enable`** —
под какой вопрос затачивается разбор.
Фокус не только раскрывает профильную секцию, но и приглушает остальные, а заодно
задаёт модели акцент внутри разбора по стадиям.

Новые role-aware фокусы:

* `vision` — obs/sen, деварды, детект и информация вокруг объективов;
* `tempo` — руны, ранние киллы/участие, выход с линии, первые тайминги;
* `initiation` — входы в бой, контроль, поглощённый урон и пространство;
* `enable` — стаки, вижн, лечение, участие и командные/защитные предметы.

```bash
python -m dota2coach analyze 8931432366 --hero "Phantom Lancer" --depth quick --focus laning
```

Порядок величин на 54-минутном матче:

| | full | laning | fights | farm | draft |
|---|---|---|---|---|---|
| **quick** | 15 КБ | 11 КБ | 29 КБ | 18 КБ | 13 КБ |
| **deep** | 38 КБ | 14 КБ | 36 КБ | 24 КБ | 16 КБ |

`--focus fights` тяжелее остальных намеренно: это поимённая раскладка каждого боя,
ради которой флаг и существует.

## Что промпт заставляет модель делать

Промпт — это не «вот данные, разбери». В него вшита методика: правила, которые
модель обязана соблюдать, и жёсткая структура ответа. Обычный игрок получает
разбор уровня power-user, ничего не зная о промптинге.

**Правила**: каждое утверждение — с числом или таймингом из данных; общие советы
(«вардить больше», «фармить лучше») запрещены; сортировка по цене ошибки, а не по
времени; объяснять механизм, а не выдавать правило; не хватает данных — сказать
прямо; сильные стороны называть так же конкретно, как ошибки.

**Структура ответа**: Вердикт → Что получилось хорошо → Главный leak с
доказательствами → Разбор по стадиям в порядке важности → 2–4 измеримых действия
(«CS@10 ≥ 55 за счёт…», а не «фарми лучше») → 2–3 вопроса для углубления.

С `--note` перед вердиктом добавляется раздел 0 — ответ на вопрос игрока.

## Свой вопрос к разбору: `--note`

Если хочешь разобраться в чём-то конкретном, а не получить обзор «по всем фронтам»,
передай вопрос текстом (у флага есть псевдоним `--ask`):

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --note "почему я так поздно собрал Manta и стоило ли идти в Diffusal?"
```

Что меняется в промпте:

* появляется отдельная секция `## ГЛАВНЫЙ ЗАПРОС ИГРОКА` с твоим текстом;
* первым правилом методики становится «вопрос игрока — главный приоритет»;
* в структуре ответа перед вердиктом добавляется раздел 0 — ответ на твой вопрос;
* в шапку добавляется указатель на этот блок.

Заметка **не меняет объём промпта** — только приоритет разбора. Отбор фактов
по-прежнему задаётся `--depth` и `--focus`, поэтому вопрос про лайн логично
сочетать с `--focus laning`:

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --focus laning --note "почему я слил лайн против Pudge + Hoodwink?"
```

Без флага структура ответа остаётся из шести разделов, без нулевого. Пустая строка
(`--note ""`) считается отсутствием заметки.

## Уровень игрока: `--mmr`

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --mmr "Legend 3500"
```

Принимается и число, и название бракета. Если указан, модель получает прямое
указание калибровать советы под этот уровень: предлагать то, что на нём реально
исполняется, а рекомендуя приём выше уровнем — объяснять, зачем он.

## Под какую модель: `--model`

Данные и методика одинаковы для всех, отличается только упаковка.

| `--model` | Обёртка | Глубина по умолчанию |
|---|---|---|
| `chatgpt` (по умолчанию) | markdown | `quick` |
| `claude` | XML-теги `<role>`, `<match_data>`, `<player_question>`, `<method>`, `<output_format>` | `deep` |
| `gemini` | markdown | `deep` |

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --model claude
```

Claude заметно надёжнее держит границы «данные / вопрос / инструкция», когда они
размечены тегами. Дефолтная глубина — подсказка, а не правило: явный `--depth`
всегда важнее.

## Язык промпта: `--lang`

`ru` (по умолчанию), `en`, `uk`. Переключает **весь** промпт — заголовки, подписи
внутри строк, ограничения и методику, — включая указание модели отвечать на этом
языке. В вебе язык интерфейса и язык промпта переключаются одним селектором.

```bash
python -m dota2coach analyze 8931432366 --me 123456789 --lang en
```

Новый язык добавляется одним файлом в [dota2coach/i18n/](dota2coach/i18n/) —
скопировать `ru.py`, перевести значения, добавить код в `_MODULES`. Офлайн-тест
проверит, что ни один ключ не забыт.

## Прочие флаги

`--no-cache` — не брать матч из локального кэша, сходить в API заново. Сыгранный
матч не меняется, поэтому распарсенный ответ кэшируется в `.cache/` навсегда: это
экономит запросы, когда гоняешь один матч в разных режимах.

## Как это устроено

```
            CLI            веб-страница
             │                   │
             └──────► core ◄─────┘
                       │
DataSource ──► Normalizer ──► FeatureExtractor ──► BundleBuilder ──► текст
(OpenDota)     (Match)        (Features)           (промпт)
                                    ▲                   ▲
                                    └─── Policy ────────┘
                         (--role / --depth / --focus / --note)
```

CLI и веб — две тонкие обёртки над одной функцией `core.generate_prompt()`.
Генерация живёт в одном месте, поэтому обёртки не могут разъехаться.

| Модуль | Ответственность |
|---|---|
| [`core.py`](dota2coach/core.py) | сборка конвейера и `generate_prompt()` — точка входа для обеих обёрток |
| [`scaffold.py`](dota2coach/scaffold.py) | методика разбора: правила для модели и структура ответа |
| [`render.py`](dota2coach/render.py) | упаковка под модель (markdown / XML) и дефолтная глубина |
| [`i18n/`](dota2coach/i18n/) | все тексты проекта — и промпта, и интерфейса |
| [`sources/base.py`](dota2coach/sources/base.py) | контракт источника: «дай `match_id` — получи `Match`» |
| [`sources/opendota.py`](dota2coach/sources/opendota.py) | HTTP к OpenDota, заказ парсинга, кэш сырого ответа |
| [`normalize.py`](dota2coach/normalize.py) | единственное место, знающее формат OpenDota |
| [`model.py`](dota2coach/model.py) | внутренняя модель матча — общий язык приложения |
| [`constants.py`](dota2coach/constants.py) | справочники: герои, предметы, способности, баффы |
| [`policy.py`](dota2coach/policy.py) | что показывать: роль, тиры, глубина, focus и заметка |
| [`features.py`](dota2coach/features.py) | отбор фактов и производные (переломы, сборки, исходы боёв) |
| [`bundle.py`](dota2coach/bundle.py) | форматирование промпта |
| [`web/app.py`](dota2coach/web/app.py) | FastAPI: страница и `POST /api/analyze` |
| [`web/static/index.html`](dota2coach/web/static/index.html) | вся страница: вёрстка, стили и скрипт в одном файле |

### API

`POST /api/analyze` принимает `{match_id, account_id, hero, role, depth, focus,
model, lang, note, mmr}` и возвращает `{prompt, filename, size_bytes, role,
parsed, warning, …}`. `role: null` означает автоэвристику, `role: "1"…"5"` —
явное переопределение позиции своего игрока.
`depth: null` означает «взять дефолт модели». Схема — на
<http://127.0.0.1:8000/api/docs>.

Блокирующие запросы к OpenDota уходят в пул потоков, поэтому сервер не залипает
на время парсинга. Коды ошибок: 404 — матча нет, 400 — не опознан игрок (в ответ
приходит список героев матча с их account_id), 429 — лимит OpenDota, 502 — сеть,
504 — матч всё ещё парсится. Если матч распарсен не полностью, промпт всё равно
возвращается, но с предупреждением в поле `warning`.

Смысл разделения — в `DataSource`. Когда появится собственный парсер реплеев
(Тир 3), он станет ещё одной реализацией этого интерфейса и вернёт тот же
`Match`; `FeatureExtractor`, `BundleBuilder` и CLI менять не придётся.

Что именно попадает в промпт, из какого поля OpenDota и в каком режиме — в
[docs/FEATURE_SPEC.md](docs/FEATURE_SPEC.md).

## Проверка без сети

```bash
python tests/selftest_offline.py
```

Гоняет синтетический матч через весь конвейер и проверяет узкие места: срезание
шаблонов талантов, поглощение компонентов предметов, фильтр нулевых баффов,
определение сгруппированного драфта, компактность `quick` относительно `deep`,
наличие guardrails и разделов ответа, приоритет заметки, совпадение данных между
markdown- и XML-упаковкой, полноту всех трёх словарей и отсутствие русских строк
в английском промпте. Дополнительно сравнивает carry и hard support на одном
матче: role override, набор метрик, правила смертей, role-aware бенчмарки и новые
`vision/tempo/initiation/enable` focus.

## Что не коммитится

`.env`, `output/`, `.cache/` — в `.gitignore`.
