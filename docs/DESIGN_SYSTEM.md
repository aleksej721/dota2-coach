# DESIGN_SYSTEM — аналитическое рабочее пространство

Статус: действующий дизайн-код веб-интерфейса. Страница пока остаётся одним
самодостаточным [`index.html`](../dota2coach/web/static/index.html), но её
визуальная система уже рассчитана на будущий Match Explorer из
[`PRODUCT_VISION_AND_ROADMAP.md`](PRODUCT_VISION_AND_ROADMAP.md).

Документ нужен как ограничитель: новая функция переиспользует описанные здесь
surface, state, spacing и visualization patterns. Случайный декоративный эффект
не добавляется только потому, что выглядит интересно в изоляции.

## Характер продукта

Цель — **спокойный premium desktop analysis product с Dota-характером**.

Интерфейс должен восприниматься как рабочее место тренера:

* сначала состояние матча и доказательства;
* затем вывод и действие;
* декор не конкурирует с цифрами;
* плотность выше у таблиц и графиков, ниже у coaching-текста;
* каждый сильный вывод можно проверить в данных.

Liquid Glass больше не является базой. Основные поверхности плотные и
непрозрачные. Прозрачность допустима только у modal backdrop, tooltip и других
временных верхних слоёв, где она помогает показать контекст под ними.

## Визуальная иерархия

Пять уровней, каждый со своей задачей:

1. **Canvas** — нейтральный фон приложения.
2. **Workspace surface** — крупная область формы, dashboard или coach panel.
3. **Section surface** — график, таблица, draft/build block.
4. **Interactive surface** — input, segmented control, button, selected range.
5. **Overlay** — modal, tooltip, context menu.

Глубина выражается прежде всего разницей тона и границей. Большая размытая тень
не должна быть единственным способом отделить элементы.

## Цветовые роли

Единственный источник значений — `:root` и `:root[data-theme="light"]`.

| Роль | Токен | Применение |
|---|---|---|
| canvas | `--bg` | фон приложения |
| surface | `--glass-bg` | основные панели; legacy-имя временно сохранено |
| raised surface | `--surface-raised` | выбранный сегмент, toolbar, overlay |
| muted surface | `--surface-muted` | footer формы, вложенные панели |
| selected surface | `--surface-selected` | активный контрол без яркой заливки |
| field | `--field-bg` | input, select, code area |
| outline | `--glass-border`, `--field-border` | разделение областей |
| primary | `--accent` | главное действие, focus, выбранный диапазон |
| text | `--text`, `--muted`, `--faint` | три уровня текстовой иерархии |
| semantic | `--radiant*`, `--dire*` | только сторона и относящиеся к ней данные |
| feedback | `--danger*`, `--warn*` | ошибка или предупреждение |

Radiant/Dire не являются цветами навигации или основных кнопок. Они отмечают
сторону, исход, соответствующую линию графика или игровое событие. Их нельзя
использовать как декоративную двухцветную заливку без смысла.

Обе темы проектируются отдельно. Светлая тема не получается автоматической
инверсией тёмной; у неё свои surfaces, borders, shadows и приглушённые
семантические цвета.

## Фон

Фон почти неподвижен и состоит из двух дешёвых слоёв:

* слабая вертикальная подсветка primary в верхней части;
* едва заметная сетка, связывающая форму с будущими charts и timeline.

По краям допустим очень слабый семантический оттенок Radiant/Dire. Летающие
орбы, искры, световой sweep, плёночный шум, солнце, луна, руны и другие
узнаваемые фигуры отключены. Атмосфера не должна выглядеть как screensaver.

## Форма и радиусы

Радиусы меньше прежних и подчинены назначению:

| Токен | Значение | Где |
|---|---|---|
| `--r-xs` | 6px | data chips, компактные markers |
| `--r-sm` | 9px | кнопки, inputs, segmented controls |
| `--r-md` | 12px | toolbar, grouped control |
| `--r-lg` | 16px | workspace panels и modal |
| `--r-full` | 999px | только круглая ручка slider/switch |

Шестиугольники, ромбы, clip-path-фишки и shape morph не являются языком
управления. Номер секции — обычный tabular number с вертикальным divider.

## Сетка и отступы

Базовая шкала остаётся кратной небольшому набору:

`--space-1` 6px · `--space-2` 10px · `--space-3` 16px · `--space-4` 24px ·
`--space-5` 32px.

Текущая форма использует три равные колонки и занимает до 1240px. Match
Explorer перейдёт на 12-колоночную сетку, где:

* match header занимает всю ширину;
* main timeline — 8 колонок;
* summary/coach rail — 4 колонки;
* две сравниваемые команды получают симметричные области;
* все вертикальные швы совпадают между секциями.

На мобильном сетка становится одной колонкой. Порядок определяется смыслом:
итог → ключевой момент → график → детали → действие, а не desktop-позицией.

## Типографика

Используется системный sans-serif стек без внешнего запроса. Display-serif
убран: заголовок продукта теперь выглядит как часть рабочего инструмента.

* product mark — 21px, плотный вес, небольшой отрицательный tracking;
* page title — 22–28px;
* section title — 12px uppercase только для навигационных/структурных меток;
* body — 14–15px;
* data labels — 11–13px с tabular numbers;
* code/raw prompt — mono 12–13px.

Uppercase нельзя использовать для длинного текста или coaching-вывода.

## Controls

### Основное действие

Одна solid primary-кнопка на локальную область. Градиент, блик и постоянное
свечение убраны. Hover меняет elevation на один уровень, pressed возвращает
элемент на плоскость.

### Выбор одного из N

Используется segmented control с общей подложкой и спокойной выбранной surface.
Выбранный элемент не меняет размер и форму. Role icons могут дополнять подпись,
но не определяют геометрию кнопки.

### Inputs

Inputs лежат на плотной field surface. Hover усиливает border. Keyboard focus —
контрастная граница плюс кольцо `0 0 0 3px var(--accent-soft)`, без glow.

### Advanced settings

Кликабельна только видимая прямоугольная кнопка. Summary рядом с ней не входит
в hit area. Раскрытие сохраняет height-анимацию существующего компонента.

### Time range

Две ручки и активный track являются одним компонентом и используют один state.
Во время drag любые transitions ручек, fill и value labels отключаются. После
отпускания допустимо короткое сглаживание. Native range inputs остаются
источником клавиатурной доступности.

## Состояния и движение

State layer остаётся общим механизмом поведения:

* hover — 8%;
* focus — 10%;
* pressed — 12%.

Одна реакция соответствует одному состоянию. Нельзя одновременно менять фон,
добавлять glow, scale и ripple для одного hover.

Разрешённые анимации:

* появление/скрытие контента;
* раскрытие advanced;
* изменение выбранного диапазона;
* переход между состояниями segmented control;
* появление данных после ответа.

Декоративные бесконечные циклы запрещены. Анимации используют преимущественно
`transform` и `opacity`; движение данных не должно задерживать сам state.

При `prefers-reduced-motion: reduce` переходы становятся практически
мгновенными, а необязательные декоративные слои отсутствуют.

## Cards, tables и charts

Карточка существует только для самостоятельной смысловой единицы. Нельзя
вкладывать карточки друг в друга ради каждой цифры.

Data cards содержат:

* короткий label;
* основное значение;
* контекст сравнения;
* источник и гранулярность при необходимости;
* semantic state только если он доказан.

Для всех charts обязательны:

* подписанные оси и единицы;
* общий time-range selection;
* tooltip, доступный с клавиатуры;
* явные gaps вместо дорисованной линии;
* data-source/granularity label;
* одинаковое кодирование сторон во всех разделах;
* достаточный контраст без опоры только на цвет.

Линии OpenDota с минутной гранулярностью не сглаживаются так, будто между
точками известна точная траектория. Replay tick-data и OpenDota minute-data
визуально и текстово различаются.

## Prompt и coaching

Prompt — технический артефакт внутри Coach panel, а не главная поверхность
продукта. По умолчанию показываются вывод, evidence и следующий шаг. Raw prompt
открывается по явному действию и сохраняет copy/download/feedback.

Сильное coaching-утверждение должно иметь переход к связанному временному окну
или evidence block. UI различает `observed`, `derived`, `inferred` и `unknown`.

## Доступность

* Интерактивная цель — минимум 44×44px на touch, если она не является частью
  стандартного текстового control.
* Native input/select/range остаётся источником истины.
* Все действия доступны клавиатурой.
* Focus-visible никогда не удаляется без замены.
* Modal удерживает фокус и возвращает его инициатору.
* Status/error используют `aria-live` там, где состояние меняется асинхронно.
* Графики получают текстовое summary и не полагаются только на hover.
* RU/EN/UK проверяются на переполнение, а не только на наличие переводов.

## Производительность

* Нет обязательного внешнего шрифта или UI-библиотеки.
* Фон не содержит непрерывных анимаций.
* Interaction state обновляется сразу, без transition-lag.
* Большие charts и tables загружаются по разделам.
* Layout не должен пересчитываться на каждом pointer move.
* Любой новый эффект проверяется в обеих темах и при reduced-motion.

## Переходный период

В `index.html` пока остаётся legacy CSS старой glass-системы, после которого
идёт слой `Analysis workspace foundation`. Это сознательная безопасная миграция:
поведение формы не переписывается одновременно с визуальной системой.

По мере появления Match Explorer старые правила удаляются секциями. До полного
удаления итоговое отображение определяется последним foundation-слоем, а этот
документ описывает именно его, не legacy-блоки выше.
